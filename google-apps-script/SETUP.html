研究者／部署管理者使用 · v2.0 · 2026-10-08

讓三關的作答，
存進你的 Google 試算表。

網站前端已提供 User ID、前測、政策動畫、後測一、後測二、結果回顧與續玩。Google Sheets 使用獨立接收程式；金鑰留在網站伺服器及 Apps Script 指令碼屬性，不放在玩家的瀏覽器。

目前連線狀態：尚未設定。沒有試算表及接收網址時，網站僅供試玩，不會宣稱資料已寫入 Google Sheets。啟用之前，需以明確標記的測試資料驗證實際寫入。

1. 準備試算表與接收程式

  1. 建立或選定一份你擁有的 Google 試算表；試算表本身不需要公開。網址 /spreadsheets/d/ 後方到下一個斜線之間是 Spreadsheet ID。
  2. 在試算表選擇「擴充功能 → Apps Script」，把本資料夾的 Code.gs 放進指令碼專案。
  3. 在 Apps Script「專案設定 → 指令碼屬性」加入 SHEET_ID（Spreadsheet ID）及 SHARED_SECRET（至少 32 字元的隨機值）。此值稍後要與網站伺服器設定相同。
  4. 執行 setup()。它會新增 ocean_summary 分數總表及 ocean_records 原始紀錄表與欄位，不清除原有工作表；遇到同名但欄位不同的表格會停止。第一次執行需由擁有者完成 Google 的試算表授權。
  5. 選「部署 → 新增部署 → 網頁應用程式」，以擁有者身分執行，允許網站伺服器呼叫。接收端需要不經互動登入即可連線的部署選項（通常為「任何人」）；學校帳號若限制此選項，需使用機構允許的部署方式，不能繞過管理政策。
  6. 保存以 /exec 結尾的部署網址。/dev 是編輯者測試網址，不能作為正式接收網址。

接收網址只接受帶正確伺服器金鑰的資料，不提供讀取研究資料的介面。玩家不用取得試算表編輯權限。

2. 設定網站伺服器

環境變數內容
SHEETS_WEB_APP_URLApps Script 的 /exec 網址。
SHEETS_SHARED_SECRET與指令碼屬性 SHARED_SECRET 相同；在部署平台標記為秘密值。
RESEARCH_COLLECTION_ENABLED設成 true 才啟用寫入；預設未設定即關閉。

Sites 使用原生環境變數設定後重新部署。其他支援此 Vinext／Cloudflare Worker 專案的主機，需提供同等伺服器環境變數。不能只上傳靜態 HTML，否則 /api/record 及秘密值保護會失效。

本機使用忽略版控的環境設定檔；.env.example 只有變數名稱，沒有真實秘密值。不要把秘密值寫入公開 JavaScript。

3. 驗證後再收案

  1. 由部署管理者以 isTest: true 的測試請求完整送出 pre、post1、post2。若用遊戲頁面試寫，使用 TEST_ 開頭的代碼，程式會標記 is_test=true；並在試算表確認該標記。
  2. 在 ocean_summary 確認同一 session_id 只有一列，三個分數及兩個差值正確。例如 3、5、4 分，差值應為 +2、+1。ocean_records 同時保留三筆逐關原始作答。
  3. 重送同一筆資料應收到 duplicate 確認，列數維持不變；更動同一紀錄的答案應被拒絕。
  4. 暫時使用錯誤連線設定測試故障時，介面必須顯示未儲存並可重試，不可以顯示成功。
  5. 完成研究者聯絡窗口、同意說明、保存期限、題庫審閱、試測與機構所需程序，再啟動正式招募。

只量一件事：政策正確認知

主要量測構念只有「政策正確認知」，分別在三個時間點記錄。每關 6 題，答對 1 題得 1 分，答錯或選「我還不確定」得 0 分；不額外施測態度、動機或信心。

主要分析欄位（3 個）意義與範圍
pre_score第一關前測，0–6 分。
post1_score第二關後測一，0–6 分。
post2_score第三關新情境後測二，0–6 分。

進步就是多答對幾題

進步分數 ＝ 後測分數 − 前測分數。gain_post1 = post1_score − pre_score；gain_post2 = post2_score − pre_score。這兩個欄位是由既有分數自動算出的差值，不增加問卷或量測構念。不使用百分比增益或正規化公式。

正值＝多答對幾題；0＝答對題數相同；負值＝少答對幾題。未完成的關卡與差值保持空白，不能當成 0 分。

遊戲自動儲存，總表每次遊玩一列

每關完成就自動送出；短暫失敗時自動重試最多兩次，再保留手動重試及下載備份。重新開啟頁面並點「繼續上次進度」時，會繼續送出尚未確認的同一份資料。收到接收端確認後才顯示已儲存。

ocean_summary 是主要分析用總表。同一 session_id 始終更新同一列，依序填入三個分數與兩個差值；user_id 是研究代碼。重複遊玩產生新的 session_id，不覆寫上一次結果。

其他欄位 completed_phases、is_complete、is_test、版本與時間只供辨識、配對與篩選，並非額外學習成效變數。正式配對分析需排除測試資料，並明確處理未完成和重複參與者。

ocean_records 保留每關的原始答案、選項順序、計分及操作時間作為查核紀錄。若總表寫入中斷，重送會從原始紀錄修復總表，不會重複新增該關，也不會讓玩家收到錯誤的成功通知。

教育研究的解讀範圍

先報告三個分數及兩次平均差值即可描述本次作答變化。第三關為新情境；題本尚未驗證等值，單組前後測也無法排除重測與題目差異，不能僅憑差值宣稱遊戲造成學習提升或符合 SSCI 發表要求。正式研究需先完成題目審閱與試測。

本版取代舊版 8 題知識＋態度問卷方案。User ID 是自填代碼，不是身分驗證；同一人的重複參與處理方式需預先指定。

中英文與研究紀錄

首次開啟預設為繁體中文；右上角可切換英文，網站會記住玩家主動選擇的語言。切換不會改變題目編號、選項 ID、計分或目前進度。

逐題 answers_json 中的 language 記錄送出答案時的語言；languagesSeen 記錄此次呈現題目期間顯示過的語言。這些是施測背景資料，不增加學習成效變數。舊紀錄沒有此欄位時保持缺漏，不假定為中文。中英文題本尚未完成跨語言等值驗證，研究分析需辨識單語與混合語言作答。

部署與維護

程式已以 Sites 的 Vinext 模板建置。一般開發使用 npm run dev，型別檢查 npx tsc --noEmit，測試 node --test tests/assessment.test.mjs，建置 npm run build。Sites 發布使用已綁定的 project_id 與平台發布工具，不要重新建立重複網站。

網站依使用者要求開放公開單人體驗，不要求玩家登入 ChatGPT。玩家自行設定 User ID，每次遊玩另有 session_id；不需組隊或等待。Google Sheets 啟用狀態仍由伺服器設定控制，公開遊戲不代表公開研究試算表。

Google 接收程式更新後需建立新部署版本並沿用端點。研究正式收案期間固定題庫、新聞、程式與計分版本；任何必要更新另建版本，不混為同一個介入。
