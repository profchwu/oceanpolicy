v5 即時治理：第一關含即時回饋，因此是初始遊玩表現，不是純前測。後兩關使用相同政策工具，可能有記憶與練習效應；不可宣稱已驗證遠遷移或因果成效。三項行為指標為政策選擇、成效監測、事件應變；每項每關 0–3 分。場景指數不是研究量表或真實氣候預測。

海洋指揮中心 v5：研究資料連線

v5 新增三座預算救援海島，training 為過程紀錄而非第四項成效變數。請依 instrument_version 分開分析 v3 與 v5。新版以政策選擇、成效監測與情境應變三種遊玩行為評量。舊版單選題資料保留；請使用本頁的 v5 接收程式，不要直接覆寫舊版資料欄位。

目前網站可試玩。只有設定完成、真實寫入確認通過，才應開始招募研究參與者。模擬測試通過不代表 Google 已完成連線；此量表亦尚未完成專家效度與信度驗證。

1. 建立接收端

  1. 開啟研究者擁有的 Google 試算表，從「擴充功能 → Apps Script」建立專案。試算表維持私人權限，無須公開研究資料。
  2. 將 Code-v5.gs 全部貼入 Apps Script。它是完整的獨立接收程式；不要同時貼入舊版 Code.gs 或 receiver-v3.js，以免重複函式。
  3. 在「專案設定 → 指令碼屬性」新增 SHEET_ID（試算表網址 /d/ 與 /edit 之間的 ID）及 SHARED_SECRET（至少 32 字元的隨機密鑰）。密鑰只放在伺服器設定，不要貼在聊天、網頁或前端程式。
  4. 執行一次 setup()，由研究者完成 Google 授權。它新增 ocean_behavior_events 與 ocean_behavior_summary，不修改舊版工作表。若表頭衝突會停止，避免覆蓋資料。
  5. 部署為「網頁應用程式」，執行身分選研究者；存取範圍需允許網站伺服器呼叫。接收端另以共享密鑰驗證請求。複製正式部署的 /exec 網址。網域管理員若禁止匿名 Web App，需要改用機構允許的後端。

官方說明：Apps Script 網頁應用程式、指令碼屬性、Lock Service。

3. 資料結構與計分

ocean_behavior_events 是每個同步版本的不可覆寫原始快照；離線時會合併待送快照，最新快照包含先前全部首次選擇。每個 session_id:revision 只寫入一次。原始 JSON 保留選項順序、呈現及提交時間、語言、學習區選擇；此版本 training 欄位保留為空陣列。

ocean_behavior_summary 每次遊玩只有一列，隨進度更新。相同 User ID 的不同 session_id 分開保存；User ID 並非身分驗證，重複遊玩的納入規則需研究者預先訂定。

post1_*、post2_*第二、三關的相同三種變數

4. 10 分鐘與資料缺失

按開始後設定固定 600 秒截止時間，重新整理、切換分頁與關閉頁面不會重設。瀏覽器暫停執行時，恢復頁面後立即檢查截止時間。到期後不接受新決策，結束時間記為原截止時間。三次觀察未完成的變數留空，不補成零分；已完成變數仍可計分。網路儲存與結果頁檢視不阻擋遊戲結束。

網站每次決策先寫入本機暫存，再背景同步。斷線時顯示未確認狀態；恢復網路後重試。同一份紀錄重送會修復未完成的摘要更新，不重複寫入原始資料。若仍失敗，使用「下載自己的紀錄」保存 JSON，不要宣稱已上傳。公共網站不能保證使用者關閉前尚未確認的資料一定到達 Google。

5. 版本、研究與維護

正式資料收集期間凍結新聞、任務、翻譯及評分規則；修改時更新 instrument_version。第三關是即時近遷移，不是延宕保留。三個指標各只有三次觀察，需試測難度、信度、專家效度及中英文可比性；單組前後測不能單獨支持因果推論。研究同意流程、資料保存期限與聯絡窗口須依實際研究計畫提供。

Apps Script 有配額與並行限制，公開大量招募前先做符合預期人數的負載檢查。此版本每人最多 32 份同步快照，離線合併會較少。若日誌規模增加，應改為索引化資料庫加批次匯出，避免每次掃描整張工作表。官方：服務配額。

開發者修改行為資料契約或評分後，執行 node scripts/build-rts-receiver.mjs 重新產生接收程式，再執行 node --test tests/rts.test.mjs tests/rts-receiver.test.mjs。既有 v2 工作表與接收程式保留，作為相容性與回復參考。
